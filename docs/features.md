# CodeGate（码界）功能特性全景规划

---

## 一、系统背景与使命

随着大语言模型在企业内部软件研发与日常办公中的深入应用，团队面临着严峻的算力接入与治理挑战：
- **费用与账号分散**：多位工程师使用 Claude Code、OpenCode、Cursor 或各类 AI 插件，各自绑定个人账号或寻求第三方镜像，不仅缺乏统一结算与成本审计，而且存在企业核心代码泄露的安全隐患。
- **服务商稳定性与限流痛点**：晚高峰时段主流大模型（如 DeepSeek、Kimi 等）频繁出现 429 频控或 503 宕机，业务系统（如 `code-shield` 自动化代码扫描流水线）缺乏跨账号/跨供应商的自动负载均衡与平滑容灾机制。
- **显存算力利用率低下**：多轮长上下文代码问答中，请求被简单随机分发到不同推理实例，导致大模型显存内的 Prompt KV Cache 无法命中，首字响应时延（TTFT）大幅恶化。
- **运维与交付负担沉重**：常见开源网关方案通常强制依赖 Redis、MySQL、Docker、Node.js 运行时或复杂插件，对于追求精简、敏捷的内部系统而言，运维基础设施成本过高。

**CodeGate（码界）** 旨在成为企业内部**统一、可靠、智能且极轻量的大模型接入基础设施**，在保障数据安全与成本可控的前提下，全面赋能内部系统与全员研发办公。

### 1. 业务管理价值
- **资产与数据安全收敛**：外部供应商真实 API Key 均收敛于网关底层，不向任何客户端暴露；全链路访问日志脱敏，密钥零外泄。
- **精细化配额与成本管控**：支持 RPM（每分钟请求频次）、RPD（每日请求总额度）、跨午夜可用时间段策略，按部门与用户精准设限，从根本上杜绝意外消耗与恶意刷量。
- **极致轻量降低 TCO**：摒弃外部 Redis / MySQL / 消息队列，单个可执行文件内嵌前端与纯 Go SQLite，极低资源占用（数十兆内存即可高并发承载）。

### 2. 技术架构价值
- **生产级高可用与平滑容灾**：多物理实例负载均衡（加权轮询/最少连接）+ 主动探针熔断自愈 + **默认模型 Fallback 智能降级**，确保下游关键链路不停摆。
- **Prompt KV Cache 会话粘性加速**：采用 HRW (Rendezvous Hashing) 算法，按 Session-ID 锁定同一多轮对话实例，复用显存上下文，首字延迟（TTFT）下降 50%~80%。
- **实例级细粒度并发控制**：原子 CAS 无锁并发计数，防止瞬时并发流量打爆单物理后端或私有显卡推理集群。

### 3. 研发与员工赋能价值
- **标准生态即插即用**：100% 兼容 OpenAI 标准 API，修改 Base URL 与 Key 即可无缝接入各类 SDK、开源框架与 IDE 插件。
- **深度赋能 AI Coding Agent**：专为 Claude Code、OpenCode 定制 `/v1/responses` 直通代理端点，并支持 SSE 长连接心跳保活。
- **开箱即用 Web 交互台**：无需额外安装客户端，浏览器登录即可使用现代化 Chat 界面，支持 Markdown 渲染、代码高亮与思维链（Reasoning）气泡折叠。

## 五、核心特性模块详述

### 特性模块 1：统一协议接入与多模式代理

#### 1.1 OpenAI Chat Completions 协议原生兼容 (`/v1/chat/completions`)
- **标准接口覆盖**：支持标准请求格式，兼容 OpenAI 官方 Python/Node SDK、LangChain、LlamaIndex 等。
- **流式（SSE）与非流式透传**：支持逐字打字机增量响应与完整聚合响应。
- **高级模型特性支持**：
  - **Tool Calling / Function Calling**：完整支持工具调用协议与参数传递。
  - **思维链过程（Reasoning Content）**：原生支持 DeepSeek-R1 等推理大模型的思考过程透传。
- **长连接心跳保活（Keep-Alive Ping）**：
  - 针对复杂代码生成等长耗时场景，后台协程每隔固定时间发送 `: ping\n\n` 注释事件，避免网关前置代理断开空闲连接。
- **轻量请求解析优化**：
  - 仅提取路由与计费必须字段（`model`, `stream` 等），不对数万字符的 `messages` 做全量 JSON 反序列化，保障极高吞吐与极低内存占用。

#### 1.2 Responses API 原生直通代理 (`/v1/responses`)
- **专为现代 Coding Agent 设计**：深度适配 OpenCode、Codex CLI 等现代代码编写智能体。
- **直通代理模式（Passthrough）**：在提取必要调度元信息后，载荷字节保持原始直通，杜绝任何参数畸变或丢字段。

#### 1.3 模型目录动态查询 (`/v1/models`)
- 兼容标准 `/v1/models` 端点，根据当前调用者的身份和配额白名单，动态输出其具备访问权限的可用模型清单。

#### 1.4 精确 Token 计量体系
- 放弃本地分词估算，直接从后端服务商在 SSE 终结帧或响应体中返回的权威数据中提取真实 `input_tokens` 与 `output_tokens`，通过流式清理钩子（defer）安全落盘。

### 特性模块 2：智能流量调度与高可用保障

#### 2.1 智能负载均衡策略
- **权重轮询（Weighted Round-Robin）**：基于物理实例配置权重平滑分发。
- **加权最少连接（Weighted Least-Connections）**：动态追踪后端正在处理的活跃请求数，优先调度至最空闲节点。

#### 2.2 KV Cache 亲和性会话粘性调度（Session Affinity）
- **痛点攻克**：多轮对话中，若连续请求被分散分发，每次都需要重新计算上下文显存，导致首字延迟（TTFT）大幅增加。
- **HRW 随机哈希算法**：采用 Highest Random Weight (Rendezvous Hashing) 算法，对携带相同会话特征的请求计算确定性节点评分。
- **多源会话特征提取**：
  - Header 优先级：`X-Session-ID`, `X-Conversation-ID`, `Session-ID`, `Conversation-ID`, `X-Chat-ID`。
  - Body 优先级：`session_id`, `conversation_id`, `chat_id`。
  - 兜底：未携带会话标识时自动回退为加权最少连接。
- **溢出保护（Spillover Protection）**：首选亲和节点达到最大并发上限或发生故障时，自动降级至次优节点，兼顾亲和加速与系统整体高可用。

#### 2.3 默认模型容灾降级（Default Model Fallback）
- 当目标模型无可用后端、全部节点异常或被限流打满时，网关根据策略设定的 `default_model` 自动平滑转接至备选模型，对下游业务提供保底可用性。

#### 2.4 主动式健康检查机制
- 后台周期性探测各后端实例可用性，连续失败达到阈值自动熔断并移出路由池；节点恢复后秒级自动加回。支持在控制台手动一键刷新全局健康状态。

### 特性模块 3：多维度配额、限流与访问控制

```
                    ┌────────────────────────────┐
                    │    QuotaPolicy 策略引擎    │
                    └─────────────┬──────────────┘

         │                        │                        │
```

#### 3.1 速率限制（Rate Limit / RPM）
- 内存高性能滑动时间窗口计数器，超出上限即时返回 HTTP 429 并携带标准 Retry-After。

#### 3.2 每日请求配额（Request Quota Daily / RPD）
- 采用**内存计数器 + 批量异步持久化 + 本地缓存**的高性能混合设计，抗击海量并发，降低数据库写压。

#### 3.3 动态可用时间段控制
- 支持设定生效时段（如工作时间 `09:00-18:00`，或限制耗算力任务仅在闲时 `22:00-06:00` 运行）。
- 原生支持跨午夜判断逻辑，时段不匹配时即时拦截并友好提示。

#### 3.4 模型白名单与权限隔离
- 策略内支持明确授权的模型列表或通配符 `*`，未获授权的模型调用被即时拦截。

### 特性模块 4：服务过载保护与安全防护

#### 4.1 后端级细粒度并发控制（Per-Backend Concurrency）
- 面向单个物理 Backend 实例的 `max_concurrency` 控制，采用原子 CAS（`atomic.CompareAndSwapInt32`）并发占槽与释放，杜绝高并发超发击穿。

#### 4.2 客户端类型动态过滤（Client Filter）
- 基于 User-Agent 字符串配置黑名单规则，拦截未经授权的爬虫或危险脚本，按调用方协议格式（OpenAI / Anthropic）返回对应标准 403 错误，支持规则热加载。

#### 4.3 HTTP 传输层防御与优雅停机
- 支持大模型超长生成所需的 `write_timeout: 30m`，防止连接被过早切断。
- 捕获 SIGINT / SIGTERM 操作系统信号，执行优雅退出（Graceful Shutdown），平稳等待正在传输的流式请求收尾并 Flush 缓存日志。

### 特性模块 5：模型与物理后端实例治理

#### 5.1 虚拟模型与物理实例解耦（1:N）
- 逻辑模型对用户暴露统一标识，底层挂载多个具有独立 Base URL、API Key、权重与并发上限的物理后端。

#### 5.2 模型参数透明注入与重写（`model_params`）
- 支持在网关层静默补充或覆盖参数（例如强制注入 `enable_thinking: false` 提升吞吐，或配置 `__user_agent__: "CodeGate/1.0"` 转换为标准 HTTP Header）。

#### 5.3 上游网关模型一键批量导入
- 支持输入第三方 OpenAI 兼容网关地址与密钥，自动拉取其模型清单并批量一键生成本地映射，大幅降低初始化成本。

### 特性模块 6：组织用户体系与凭证管理

#### 6.1 角色权限控制（RBAC）
- **管理员（Admin）**：全权管理全局配置、用户审核、模型/后端维护、配额编排与审计检索。
- **普通用户（User）**：登录控制台查看自身配额、自建与吊销 API Key、使用在线 Chat 界面以及查看个人调用流水。

#### 6.2 注册审批流与企业 SSO
- 支持员工自主注册（待审核激活），或通过企业统一 SSO（OIDC / Azure AD）免密登录并自动同步账号。

#### 6.3 会话滑动过期刷新机制
- 网关响应头静默回传刷新凭证，前端自动续期，避免长会话期间突然被踢下线。

#### 6.4 API Key 自助生命周期管理
- 用户可创建多场景 Key，支持设定有效天数、绑定可用模型范围，支持一键作废。

### 特性模块 7：全链路审计、观测与排障诊断

#### 7.1 全结构化脱敏 Access Log
- 完整采集调用时间、用户、IP、UA、路径、模型、状态码、输入/输出 Token、总耗时与 TTFT 首字延迟；自动对 Authorization 等关键头脱敏。

#### 7.2 流式响应异步聚合还原
- 后台异步解析逐字流式 SSE 报文，将 Prompt 与最终回复聚合为完整文本，便于审计与复盘。

#### 7.3 4 阶段原始报文转储（Raw Dumps）
- 生产排障利器，记录四个关键阶段的报文：
  1. `1_raw_request.txt`：客户端原始输入；
  2. `2_converted_request.txt`：发往后端的重写请求；
  3. `3_{code}_backend_response.txt`：后端返回的原始响应；
  4. `4_{code}_converted_response.txt`：网关最终回传给客户端的报文。
- 秒级判定故障根因（是网关参数问题还是上游供应商故障）。

#### 7.4 自动日志轮转
- 定时任务自动清理超过保留期限（默认 7 天）的历史日志，保障本地磁盘安全。

- 多维条件筛选（状态码、模型、用户、时间），点击任意日志行即可在右侧抽屉展开查看完整 Prompt、回复明细、脱敏 Header、耗时与 Token 统计。

### 特性模块 9：极简交付与运维工程特性

- **单二进制自包含交付（Single Binary）**：
  前端编译产物通过 Go 1.16+ `embed.FS` 原生打入二进制。部署只需一个可执行文件和一个 `config.yaml`，完全脱离 Nginx 与 Node.js 运行时依赖。
- **纯 Go 零 CGO 架构（Pure Go SQLite）**：
  使用 `modernc.org/sqlite` 驱动，不依赖本地 gcc/glibc，轻松实现跨平台交叉编译（Linux AMD64/ARM64, macOS, Windows），Docker 镜像体积极小。
- **配置动态热重载（Hot-Reloading）**：
  内置事件发布订阅机制，控制台修改模型、后端、限流策略后，网关在毫秒级内自动热更新，现有通信长连接完全不受干扰。

## 六、典型应用场景实践

### 场景 1：内部研发工具接入（Claude Code / OpenCode / Cursor）
- 统一在网关配置高性能后端，开放 `/v1/chat/completions` 与 `/v1/responses` 接口；
- 为每位研发人员分配带速率限制的专属 API Key；
- 研发人员直接将终端工具的 Base URL 指向 `http://codegate.internal/v1`；
- 网关启用 SSE Keep-Alive 心跳保活，保证 Agent 大段代码生成稳定可靠，全量调用可审计归属。

### 场景 2：赋能 `code-shield` 代码安全检视高可用
- `code-shield` 自动化扫描产生密集的并发 LLM 检视请求；
- 在 CodeGate 中配置多个上游账号与实例，启用加权最少连接与实例级原子 CAS 并发控制；
- 当主模型供应商偶发 503 或 429 时，网关秒级容灾切换或降级至备用模型，保障 CI/CD 流水线永不中断。

### 场景 3：长文本多轮交互下的 KV Cache 亲和加速
- 客户端在多轮长对话中传递 `X-Session-ID`；
- 网关基于 HRW 哈希将同一会话的所有交互稳定路由到同一个后端节点；
- 充分命中大模型显存中的 Prompt KV Cache，首字延迟（TTFT）大幅下降，企业推理吞吐翻倍。
