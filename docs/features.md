# CodeGate（码界）功能特性全景规划

---

## 一、系统背景与使命

随着大语言模型在企业内部软件研发（如 `code-shield` 代码扫描、`code-pipeline` CI/CD）与日常研发办公中的深入应用，团队面临着严峻的算力接入与治理挑战：
- **费用与账号分散**：多位工程师使用 Claude Code、OpenCode、Cursor 或各类 AI 插件，各自绑定个人账号或寻求第三方镜像，不仅缺乏统一结算与成本审计，而且存在企业核心代码泄露的安全隐患。
- **算力计费与配额粗糙**：传统网关仅按简单请求次数（RPD）限额，无法体现不同模型（旗舰大模型 vs 轻量小模型）以及 Token 类型的成本差异，更无法引导开发者利用 Prompt Cache 降低企业支出。
- **异构协议适配痛点**：各推理端对 OpenAI Chat 协议普遍支持，但现代 Coding Agent（如 OpenCode、Codex CLI）依赖新兴的 `/v1/responses` 协议，盲目转发会导致请求被下游直接拒收或报错。
- **服务商稳定性与限流**：晚高峰时段主流大模型频繁出现 429 频控或 503 宕机，内部关键自动化流水线缺乏跨账号/跨供应商的自动分流与平滑容灾机制。
- **显存算力利用率低下**：多轮长上下文代码问答中，请求被简单随机分发到不同推理实例，导致大模型显存内的 Prompt KV Cache 无法命中，首字响应时延（TTFT）大幅恶化。

**CodeGate（码界）** 作为 `code-*` 系列核心成员，与现有系统共享企业级 **PostgreSQL** 基础设施，旨在成为企业内部**统一、高可用、协议感知且具备精准 Credits 算力核算的智能网关**。

### 1. 业务管理价值
- **资产与数据安全收敛**：外部供应商真实 API Key 均收敛于网关底层，不向任何客户端暴露；全链路访问日志脱敏，密钥零外泄。
- **精细化 Credits（积分）算力治理**：告别粗放的请求频次限制，构建以 Credits 为核心的弹性配额体系，按 Token 类型（输入/缓存命中/输出）及模型专属倍率精准计费。
- **双周期弹性配额管控（日/周）**：同时支持每日安全上限与每周总额度（每周总量设定为每日的 4 倍），既兼顾工程师攻坚日弹性用量，又锁死单周总算力预算。
- **与 `code-*` 共享 PostgreSQL**：深度融入公司基础架构，复用成熟的 PostgreSQL 集群与备份体系，运维零额外负担。

### 2. 技术架构价值
- **协议感知智能直通（Protocol-Aware Passthrough）**：保持 100% 原始载荷直通，同时智能识别后端能力，确保特定协议（如 `/v1/responses`）仅精准派发至具备该能力的节点，杜绝下游畸变与 404/405 拒收。
- **生产级高可用与平滑容灾**：多物理实例负载均衡（加权轮询/最少连接）+ 主动探针熔断自愈 + **默认模型 Fallback 智能降级**，确保关键链路不停摆。
- **Prompt KV Cache 会话粘性加速**：采用 HRW (Rendezvous Hashing) 算法，按 Session-ID 锁定同一多轮对话实例，复用显存上下文，首字延迟（TTFT）下降 50%~80%。
- **实例级细粒度并发控制**：原子 CAS 无锁并发计数，防止瞬时并发流量打爆单物理后端或私有显卡推理集群。

### 3. 研发与员工赋能价值
- **标准生态即插即用**：100% 兼容 OpenAI 标准 API，修改 Base URL 与 Key 即可无缝接入各类 SDK、开源框架与 IDE 插件。
- **深度赋能 AI Coding Agent**：专为 Claude Code、OpenCode 定制 `/v1/responses` 原生直通代理端点，并支持 SSE 长连接心跳保活。
- **开箱即用 Web 交互台**：无需额外安装客户端，浏览器登录即可使用现代化 Chat 界面，支持 Markdown 渲染、代码高亮与思维链（Reasoning）气泡折叠。

## 五、核心特性模块详述

### 特性模块 1：统一协议接入与协议感知直通代理

#### 1.1 OpenAI Chat Completions 原生兼容 (`/v1/chat/completions`)
- **标准协议支持**：完整支持标准请求体规范，无缝对接 OpenAI Python SDK、Node.js SDK、LangChain、LlamaIndex 等周边生态。
- **流式（SSE）与非流式响应**：支持 Server-Sent Events 流式增量打字机输出，同时支持非流式完整聚合输出。
- **高级能力透传**：
  - **Tool Calling / Function Calling**：完整透传大模型的外部工具调用与参数字段。
  - **思维链（Reasoning Content）**：原生支持 DeepSeek-R1 等推理模型的思维过程透传。
- **长连接与心跳保活（Keep-Alive Ping）**：
  - 针对大模型超长输出场景（如复杂代码生成、长文本推理），内置后台心跳协程，定期发送 `: ping\n\n` 保活事件，防止前置代理因空闲超时中断连接。
- **轻量请求解析与性能优化**：
  - 仅解析路由关键字段（`model`, `stream` 等），不对庞大的 `messages` 进行全量序列化与反序列化，显著降低网关 CPU 与 GC 压力。

#### 1.2 Responses API 原生直通代理 (`/v1/responses`)
- **Agent 工具专属端点**：专为 OpenCode、Codex CLI 等现代代码编写 Agent 定制，提供原生 `/v1/responses` 端点。
- **纯直通模式（Passthrough Mode）**：仅提取调度元数据，请求载荷保持 100% 原始字节直通，杜绝任何结构损失或字段畸变。

#### 1.3 后端协议能力自动标识（Capabilities Auto-Detection）
- **协议现状与挑战**：所有后端实例均天然支持 OpenAI Chat 协议，但仅有部分特定实例支持 Responses 协议。
- **自动探查与状态机**：
  - 后台健康探针定期执行探活，除检查实例基础可用性外，自动发起轻量协议探测（对 `/v1/responses` 进行端点探活）；
  - 探测到正常响应或参数格式错误（400/422）时，自动标记该 Backend 具备 `protocols: ["chat", "responses"]`；若返回 404/405 则标记仅支持 `protocols: ["chat"]`；
  - 配置文件中同样支持显式声明以覆盖自动探测结果。

#### 1.4 协议感知智能直通调度（Protocol-Aware Routing）
- **严格协议过滤**：
  - 收到 `/v1/chat/completions` 请求时，在支持 `chat` 的后端池中进行调度（通常包含所有后端）；
  - 收到 `/v1/responses` 请求时，**调度器强制只在已被标识/声明支持 `responses` 协议的物理实例池中执行负载均衡**；
  - 若目标模型下不存在任何支持 `responses` 的健康实例，网关返回标准的 HTTP 501 Not Implemented 或根据策略自动尝试具备该能力的备选模型，杜绝盲目转发导致的下游接口报错。

### 特性模块 2：Credits 算力点数与双周期弹性配额引擎

CodeGate 全面升级为基于 **Credits（算力点数）** 的精细化计费治理引擎：

```
                              ┌────────────────────────────┐
                              │    Credits 配额治理引擎    │
                              └─────────────┬──────────────┘
                    ┌───────────────────────┴───────────────────────┐
                    ▼                                               ▼
         ┌─────────────────────┐                         ┌─────────────────────┐
         │ 每日配额上限 (Daily) │                         │ 每周配额总量 (Weekly)│
         │  (防止单日意外刷爆) │                         │ (通常为每日上限的 4倍)│
         └─────────────────────┘                         └─────────────────────┘
                    │                                               │
                    └───────────────────────┬───────────────────────┘
                                            ▼
                    ┌───────────────────────────────────────────────┐
                    │            Token 差异化基准费率               │
                    │   输入: 1.0  |  缓存命中: 0.1  |  输出: 5.0   │
                    └───────────────────────┬───────────────────────┘
                                            ▼
                    ┌───────────────────────────────────────────────┐
                    │               模型倍率系数调整                │
                    │   轻量模型: 0.5x  |  标准: 1.0x  |  旗舰: 10x │
                    └───────────────────────────────────────────────┘
```

#### 2.1 Credits 计费模型与费率公式
- **Token 差异化基准费率（Base Rates）**：
  - **输入 Token（Input Tokens）**：基准费率为 **1.0 Credits / 1k Tokens**；
  - **Prompt 缓存命中 Token（Cache Read / Hit Tokens）**：享受巨幅优惠，基准费率为 **0.1 Credits / 1k Tokens**（输入费率的 1/10，激励使用长会话 KV Cache）；
  - **输出 Token（Output / Completion Tokens）**：大模型生成消耗显著更大，基准费率为 **5.0 Credits / 1k Tokens**。
- **模型倍率系数（Model Multipliers）**：
  - 每个逻辑模型支持配置专属乘数，以体现异构模型的真实算力成本差异：
    - 轻量小模型（如 `qwen-2.5-coder-7b`）：倍率为 `0.5`；
    - 通用标准模型（如 `deepseek-v3`）：倍率为 `1.0`；
    - 昂贵旗舰/推理模型（如 `claude-3-7-sonnet`, `deepseek-r1`）：倍率为 `5.0` ~ `10.0`。
- **单次请求费用计算公式**：
  $$\text{Cost}(\text{Credits}) = \frac{\text{Input} \times 1.0 + \text{CacheHit} \times 0.1 + \text{Output} \times 5.0}{1000} \times \text{ModelMultiplier}$$
- **真实 Token 精确提取**：直接从服务商 SSE 终结帧或响应体中提取官方精确的 `prompt_tokens`, `prompt_tokens_details.cached_tokens`, `completion_tokens`，彻底告别本地分词预估误差。

#### 2.2 双周期弹性配额机制（Daily & Weekly Quota）
- **每日限额（Daily Quota）**：设定每日 Credits 消耗上限，防止单日跑批脚本失控或并发刷爆；
- **每周总量（Weekly Quota）**：设定自然周 Credits 总量，**系统默认且推荐将每周配额设定为每日配额的 4 倍**（即 $Q_{\text{weekly}} = 4 \times Q_{\text{daily}}$）：
  - **业务价值**：工程师在一周 5 个工作日内可根据实际攻坚节奏弹性安排用量（例如周二需求交付多可使用至日上限），但单周整体总预算受到 4 天上限的锁定，既提供了工作日弹性，又确保了企业算力月度账单绝对受控。
- **实时预检与原子扣减**：
  - 请求进入时先在内存中校验当前日/周剩余额度；
  - 请求完成后，异步工作池在 PostgreSQL 中原子扣减对应周/日的 Credits 并记录流水。

#### 2.3 辅助配额与治理策略
- **滑动窗口速率限制（RPM）**：限制每分钟请求频次，超限即时返回 HTTP 429；
- **跨午夜可用时间段策略**：支持限定时段可用（如 `09:00-18:00`，或 `22:00-06:00` 闲时运行）；
- **模型权限白名单**：支持指定允许调用的模型列表或通配符 `*` 授权。

### 特性模块 3：智能流量调度与高可用保障

#### 3.1 协议感知 + 智能负载均衡
- **先协议过滤，后负载调度**：先根据请求类型筛选出支持该协议的可用后端集合；
- **加权轮询（Weighted Round-Robin）**：基于物理实例配置权重平滑分发。
- **加权最少连接（Weighted Least-Connections）**：优先分发至当前活跃连接数与权重比值最低的实例。

#### 3.2 KV Cache 亲和性会话粘性路由（Session Affinity）
- **HRW (Rendezvous Hashing) 算法**：对请求头（`X-Session-ID` 等）或 Body 中的会话 ID 计算确定性权重得分，精准绑定多轮对话至同一后端实例；
- **Prompt 显存复用**：配合 0.1 Credits 的缓存优惠计费，用户多轮交互首字延迟（TTFT）降低 50%~80%，同时大幅节省 Credits 消耗；
- **溢出保护（Spillover Protection）**：亲和节点达并发上限或异常时，自动平滑溢出至次优健康节点。

#### 3.3 默认模型容灾降级（Default Model Fallback）
- 当目标模型无可用后端或全部节点异常时，根据策略设定的 `default_model` 自动无缝降级转接至备用模型，保证下游业务（如代码扫描）不中断。

#### 3.4 主动式健康检查探针
- 定时向后端节点发送轻量探测请求，自动完成可用性与协议能力识别；连续故障自动熔断剔除，恢复后秒级重新纳管。

### 特性模块 4：服务过载保护与安全防护

#### 4.1 后端级细粒度并发控制（Per-Backend Concurrency）
- 面向单个物理 Backend 实例的 `max_concurrency` 控制，采用原子 CAS（`atomic.CompareAndSwapInt32`）并发占槽与释放，杜绝高并发超发击穿。

#### 4.2 客户端类型动态过滤（Client Filter）
- 基于 User-Agent 字符串配置黑名单规则，拦截未经授权的爬虫或危险脚本，按调用方协议格式（OpenAI / Anthropic）返回对应标准 403 错误，支持规则热加载。

#### 4.3 HTTP 传输层防御与优雅停机
- 支持大模型超长生成所需的 `write_timeout: 30m`，防止连接被过早切断。
- 捕获 SIGINT / SIGTERM 操作系统信号，执行优雅退出（Graceful Shutdown），平稳等待正在传输的流式请求收尾并 Flush 缓存日志与 Credits 扣减。

### 特性模块 5：模型与物理后端实例治理

#### 5.1 虚拟模型与物理实例解耦（1:N）
- 逻辑模型对用户暴露统一标识，底层挂载多个具有独立 Base URL、API Key、权重、并发上限以及协议支持能力的物理后端。

#### 5.2 模型参数透明注入与重写（`model_params`）
- 支持在网关层静默补充或覆盖参数（例如强制注入 `enable_thinking: false` 提升吞吐，或配置 `__user_agent__: "CodeGate/1.0"` 转换为标准 HTTP Header）。

#### 5.3 上游网关模型一键批量导入
- 支持输入第三方 OpenAI 兼容网关地址与密钥，自动拉取其模型清单并批量一键生成本地映射，大幅降低初始化成本。

### 特性模块 6：组织用户体系与凭证管理

#### 6.1 角色权限控制（RBAC）
- **管理员（Admin）**：全权管理全局配置、用户审核、模型/后端维护、配额编排与审计检索。
- **普通用户（User）**：登录控制台查看自身配额、自建与吊销 API Key、使用在线 Chat 界面以及查看个人调用流水。

#### 6.2 注册审批流与企业 SSO
- 支持员工自主注册（待审核激活），或通过企业统一 SSO（OIDC / Azure AD）免密登录并自动同步账号。

#### 6.3 会话滑动过期刷新机制
- 网关响应头静默回传刷新凭证，前端自动续期，避免长会话期间突然被踢下线。

#### 6.4 API Key 自助生命周期管理
- 用户可创建多场景 Key，支持设定有效天数、绑定可用模型范围，支持一键作废。

### 特性模块 7：全链路审计、观测与排障诊断

#### 7.1 全结构化脱敏 Access Log
- 完整采集调用时间、用户、IP、UA、路径、模型、状态码、输入/输出 Token、Prompt 缓存命中数、扣减 Credits、总耗时与 TTFT 首字延迟；自动对 Authorization 等关键头脱敏。

#### 7.2 流式响应异步聚合还原
- 后台异步解析逐字流式 SSE 报文，将 Prompt 与最终回复聚合为完整文本，便于审计与复盘。

#### 7.3 4 阶段原始报文转储（Raw Dumps）
- 生产排障利器，记录四个关键阶段的报文：
  1. `1_raw_request.txt`：客户端原始输入；
  2. `2_converted_request.txt`：发往后端的重写请求；
  3. `3_{code}_backend_response.txt`：后端返回的原始响应；
  4. `4_{code}_converted_response.txt`：网关最终回传给客户端的报文。
- 秒级判定故障根因（是网关参数问题还是上游供应商故障）。

#### 7.4 自动日志轮转与分区
- 定时任务自动清理超过保留期限（默认 7 天）的历史日志，保障数据库与磁盘存储稳定。

### 特性模块 9：系统交付与运维工程特性

- **共享企业级 PostgreSQL 架构**：
  与 `code-*` 系列基础设施统一，采用 GORM v2 连接 PostgreSQL。支持高并发连接池、强一致性事务以及完善的企业级冷热备份。
- **静态前端内嵌单二进制交付**：
  前端 React 构建产物通过 Go 1.16+ `embed.FS` 原生打入后端二进制。交付仅需单一可执行文件配合配置文件即可运行，无需额外配置 Nginx 静态服务。
- **配置动态热重载（Hot-Reloading）**：
  内置事件发布订阅机制，控制台修改模型、后端、限流策略后，网关在毫秒级内自动热更新，现有通信长连接完全不受干扰。

## 六、典型应用场景实践

### 场景 1：内部研发工具接入（Claude Code / OpenCode / Cursor）
- 统一在网关配置高性能后端，开放 `/v1/chat/completions` 与 `/v1/responses` 接口；
- 网关自动识别支持 `responses` 的后端节点，OpenCode 发出的直通请求只会被精准路由到对应实例，杜绝 404/405 报错；
- 为每位研发人员分配日/周 Credits 配额，大模型长会话享受 0.1 缓存优惠，全程透明可审计。

### 场景 2：赋能 `code-shield` 代码安全检视高可用
- `code-shield` 自动化扫描产生密集的并发 LLM 检视请求；
- 在 CodeGate 中配置多个上游账号与实例，启用加权最少连接与实例级原子 CAS 并发控制；
- 当主模型供应商偶发 503 或 429 时，网关秒级容灾切换或降级至备用模型，保障 CI/CD 流水线永不中断。

### 场景 3：长文本多轮交互下的 KV Cache 亲和加速与低成本结算
- 客户端在多轮长对话中传递 `X-Session-ID`；
- 网关基于 HRW 哈希将同一会话的所有交互稳定路由到同一个后端节点；
- 充分命中大模型显存中的 Prompt KV Cache，首字延迟（TTFT）大幅下降；
- 命中的 Token 享受 0.1 Credits 的极低费率，为团队大幅节省计算点数预算。
